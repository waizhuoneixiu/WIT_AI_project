# SteelScan 智检系统 · 文案 / PPT 素材（队友写稿用）

> 更新：2026-11-03。只写真实发生的数据与指标；GC10 候选未上线，不能写成“模型已提升”。

## 一句话介绍

SteelScan 是“YOLO 缺陷检测 + FastAPI 后端 + 大模型分析 + 魔搭在线演示”的带钢表面缺陷智检系统：上传图片/批次，返回缺陷类别、置信度、框位置、检验记录、人工复核和报告。当前线上模型 NEU-DET 测试集 mAP50=0.8223，图片级漏检率 1.85%。

## PPT 建议结构（7 页）

1. **封面**：SteelScan 带钢表面缺陷智检系统；检测 + 分析 + 复核 + 报告一体化。
2. **问题与目标**：人工目检疲劳/漏检/不可追溯；目标六类检测、CPU 可跑、结果可复核。关键词：2.39M 参数、CPU 23.86ms、漏检率 1.85%。
3. **数据来源**：NEU-DET 1800 张（六类/4189 框）；Severstal 6465 张（跨厂辅助）；GC10-DET 2312 张（10 类/3563 框，实验）；测试集固定 270 张。强调类别体系不同，不能混成六类标注。
4. **方法流程**：NEU 六类 → Severstal/GC10 辅助预训练 → NEU 微调 → 固定 270 张测试 → 超过 0.8223 才上线。
5. **结果**：基线 mAP50 0.8057、漏检率 2.59%；当前线上跨厂版 0.8223、0.4722、漏检率 1.85%；GC10 候选 0.8023、0.4594，未采用。讲法：跨厂版比基线提升；GC10 没超过线上，所以不换模型、不降精度。
6. **系统能力**：FastAPI 接口（检测/任务/复核/报告/WebSocket）；SQLite 留痕；DeepSeek 分析 + 断网降级；魔搭演示 + Docker/本地部署；API Key 安全。
7. **局限与下一步**：公开六类数据少；X-SDD 公开版只有分类无检测框；真实工厂六类数据需现场采集；下一步拿 200~500 张真实六类数据，在同一测试集验收；不增加 CPU 负担前提下做蒸馏/弱类优化。

## 答辩防线

- **为什么不多训几轮？** 模型已收敛；同数据重复训练只 ±0.5~1 个点波动，提升靠新数据/蒸馏，不靠刷轮数。
- **为什么不用 X-SDD？** 公开 GitHub 版本是 7 类分类图、无检测框；IEEE 检测版需账号。分类数据不能直接训练检测器。
- **GC10 为什么没提升？** 10 类金属表面缺陷与 NEU 六类类别体系不同；实际训练+测试 mAP50 0.8023 < 0.8223，所以没上线，这是诚实负结果。
- **参数/权重多大？** 2,390,950 参数（2.39M）；PyTorch 5.25MiB、ONNX 9.40MiB；CPU 约 23.86ms/张。
- **跨厂泛化怎么证明？** Severstal 是另一家钢厂，用于辅助预训练；但没有“同六类跨厂”测试集，只报告 NEU test 0.8223，不虚构跨厂六类准确率。

## 30 秒介绍（可直接复制）

> 我们的 SteelScan 系统用轻量 YOLO26n（239 万参数）做带钢六类缺陷检测，在 NEU-DET 独立测试集上 mAP50 0.8223、图片级漏检率 1.85%，CPU 单张约 24ms。后端用 FastAPI 提供检测、复核、报告和任务接口，接入 DeepSeek 做缺陷分析并支持断网降级；魔搭上有在线演示。为了提升泛化，我们尝试了 Severstal 跨厂预训练和 GC10-DET 辅助训练，最终只保留在测试集上真正超过基线的版本，没有为了换模型而降低线上精度。
