# 联调与验收计划

初始状态：待开始。队员一负责服务与模型事实，队员二负责客户端可复现过程，队员三组织执行和记录。本文的用例是计划，不代表已经通过。

## 1. 联调顺序

| ID | 工作 | 输入 | 通过条件 |
|---|---|---|---|
| I-01 | 样例契约 | 共同类别、HTTP、任务状态、WebSocket样例 | App可用样例展示成功、空结果、失败和生成中状态 |
| I-02 | 真实检测 | 模型、API、App上传 | 原始测试图返回框，类别/坐标/版本在双方一致 |
| I-03 | 问答与知识 | 知识、检测证据、一个大模型API | 问答关联当前图片/批次，引用可追溯，无依据可说明不足 |
| I-04 | 复核与报告 | 真实记录、模板 | 修正不覆盖原预测，历史与报告对应确认状态 |
| I-05 | 网络与故障 | 固定部署模式、错误注入 | 断线可恢复、重复事件不重复记录，AI失败不丢检测 |
| I-06 | 指标与价值实验 | 冻结模型/软件/数据、固定模板 | 原始记录支持指标、引用正确性、时间与成本结论 |
| I-07 | 演示与提交检查 | 已验收版本、材料 | 新设备按说明运行，画面/材料/版本一致，已知限制明确 |

I-02依赖I-01；I-03/I-04在真实检测基础上推进；I-05至I-07在完整闭环基础上验证。任何阻碍同时记录依赖方和下一步交付。

## 2. 核心用例矩阵

| 用例 | 场景 | 预期 | 证据 |
|---|---|---|---|
| V-01 | 原始测试图单框/多框 | 类别一致，框与原图对齐，版本可查 | 请求/结果、App截图、数据身份 |
| V-02 | 灰度图、图片方向、留白缩放 | 图像方向和坐标变换一致 | 原图与绘框对比 |
| V-03 | 未检出目标 | 显示未检出六类目标缺陷，不自动判合格 | 结果与界面 |
| V-04 | 损坏/超限/不支持文件 | 明确输入错误，不生成成功检测记录 | 响应与错误画面 |
| V-05 | 重复点击/请求重试 | 同一提交不产生不知情的重复记录 | 请求编号与记录数量 |
| V-06 | AI超时/无效结构 | 原检测保留，分析有失败与重试状态 | 任务快照与界面 |
| V-07 | 知识缺失/原因不确定 | 区分事实和假设，提示待补信息 | 输入、引用与回答 |
| V-08 | 切换图片/批次再问答 | 不串用旧上下文，统计来自实际记录 | 两条记录与回答 |
| V-09 | 人工修正/补充漏检 | 保存新复核与原预测，报告对应状态 | 历史与报告 |
| V-10 | 旧版本提交复核 | 提示冲突，刷新后再操作，不静默覆盖 | 版本/响应/界面 |
| V-11 | 重启后查询 | 已提交记录与复核可读 | 重启前后查询 |
| V-12 | WebSocket断线/重复事件 | 查询任务恢复，片段与记录不重复 | event_id、任务快照与界面 |
| V-13 | 工位断外网但局域网可用 | 仍可本地检测，云端功能状态明确 | 网络条件、检测和AI状态 |
| V-14 | 托管服务不可达 | 明确待重试/待上传，不宣称离线已检测 | 网络条件与界面 |
| V-15 | 批次汇总/报告导出 | 图片/框/确认数口径一致，草稿与确认可辨 | 原记录、统计、导出文件 |

合成样例可用于错误与空结果测试，但不得混入模型精度统计。性能样本、界面合成数据与正式演示素材分别登记。

## 3. 模型评价

冻结划分后，验证集用于选模和阈值，测试集不参与调参。记录六类样本数、数据清单、模型摘要、训练配置、输入尺寸、阈值和评价代码版本。报告mAP@0.5、mAP@0.5:0.95、六类AP、IoU=0.5且一对一匹配下的P/R、失败样例。

性能记录硬件、推理设备、batch、输入大小、预热、测量次数和时间范围。分别记录本地处理、网络和大模型延迟，不能将论文FPS当作本项目速度。小数据和缺乏正常样本的局限写入结论。

## 4. 大模型价值实验

先完成A“检测+固定模板”与C“检测+大模型+知识检索”。固定同一批检测证据，选难度接近的任务，交叉安排工具顺序。记录参与者背景、任务数量、完成时间、人工修改、事实/引用正确性、API延迟和成本。无行业专家时称为初步可用性测试。

约30%时间改善是目标，不是通过门槛或预设结论；事实错误、无依据建议和更长操作时间同样保留。主要验证复检和报告价值，不把表达流畅等同于检测精度提升。

## 5. 结果记录格式

每条验收记录至少包含用例ID、日期、App/服务/模型/知识版本、环境与部署模式、输入身份、操作步骤、预期、实际、证据位置、问题、修复及复测状态。状态使用未执行、通过、失败、受阻，不能预填通过。

## 6. 提交与演示检查

- 三人按新设备安装/启动说明完成一次端到端演练。
- 模型、接口、App、报告与PPT对应同一冻结版本。
- 公开数据回放、合成样例、历史备用视频明确标注。
- 部署位置、网络依赖、实际测试环境与已知失败明确说明。
- 数据、权重、代码来源可追溯，必要许可证保留；无权再分发的数据不默认打包。
- 公共材料不含密钥、聊天截图和私人联系方式；作者/署名按用户明确要求填写。
- 实际赛事文件格式、校内截止和上传状态已核对。

这些是验收与提交工作安排，不预设任何功能已经完成。
