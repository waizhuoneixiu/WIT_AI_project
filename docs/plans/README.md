# Plans执行索引

这里将[Roadmap](../roadmap.md)拆成可执行工作包，供三名队员协作。所有状态初始为待开始，具体姓名不在本稿推断。

| 方向 | 主任务 | 工作包 | 主要交接 |
|---|---|---|---|
| 队员一 | [模型与后端](01-model-backend.md) | B-01至B-12 | 合成响应、权重、真实API、记录与实验 |
| 队员二 | [KMP App](02-kmp-app.md) | F-01至F-10 | 页面、可安装App、真实流程和问题复现 |
| 队员三 | [文档、测试与答辩](03-docs-validation-presentation.md) | D-01至D-10 | 知识、模板、验收和参赛证据 |
| 三人共同 | [接口约定](04-shared-contract.md)与[联调验收](05-integration-acceptance.md) | I-01至I-07 | 同一套类别、坐标、状态、版本和发布证据 |

## 开始顺序

1. 三人确认接口约定、类编号、页面范围与验收要求。
2. 队员一交一套合成响应；队员二据此做界面；队员三同步知识条目与报告模板。
3. 后端与App先完成真实单图检测，再依次接问答、复核和报告。
4. 冻结版本后再评价，记录失败与限制，三人共同核对提交材料。

## 工作包更新

用待开始、进行中、待联调、待验收、完成、受阻表示状态；受阻时记录所缺输入及协作方。完成须能指向文件、结果或测试证据，不能只写“代码已提交”。日期调整同步Roadmap，不通过增加工作范围掩盖依赖问题。

每次协作说明四件事：已完成、当前阻碍、需要谁提供什么、下一次交付。接口技术事实由队员一提出，队员二确认使用，队员三维护文档，所有相关方共同复核。
