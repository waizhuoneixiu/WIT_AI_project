## 一、你负责把什么做出来

交付一套能被App稳定调用的检测与分析后端：接收钢材图片，运行NEU六类YOLO检测，保存证据，调用知识与大模型生成复检建议，支持人工复核、批次统计和报告。你负责技术实现；知识内容、报告模板与测试组织由队员三协助，App由队员二实现。

## 二、按顺序完成的任务

### 1. 数据与训练环境

- 从NEU官方入口取得检测版，检查图像、标注、空框/越界框、类别名称与实际数量，记录来源和摘要。
- 将标注转换为YOLO格式，逐类抽查叠框效果；输出转换脚本、类别映射和固定划分清单。
- 先检查重复与近重复，再冻结训练/验证/测试集。存在来源信息时按母图、实物或批次分组；缺少时在结果说明中保留局限。
- 记录Python、PyTorch、Ultralytics、设备和依赖版本。开发前优先复用官方训练、推理和结果解析实现，登记实际复用模块。

### 2. 首个YOLO模型

- 先训练YOLOv8n基线；如已有可用YOLO方案，先与团队确认再统一版本，不在临近联调时反复换模型。
- 用验证集选择权重和分数阈值，保留best.pt、训练配置、类别映射、划分清单与运行记录。
- 时间允许时比较YOLOv8s或一个针对性改动。首轮优先跑通和评价，避免同时加入多个改进模块。
- 输出真实测试结果：mAP@0.5、mAP@0.5:0.95、六类AP、固定阈值下P/R、典型漏检与误检。总计划初步目标为mAP@0.5≥0.75，未达目标如实分析。
- 记录batch=1、输入尺寸、预热及计时范围；目标电脑本地处理P95初步争取≤500毫秒。公布实测设备和实际值，不套用官方或他人的速度。

### 3. 可调用的推理服务

- 用Python/FastAPI封装YOLO，先让一张图可以通过接口返回类别、分数与原图坐标框。
- 上传时校验大小和类型，生成记录编号，保存原始预测与模型版本，返回任务编号。
- 将标注图作为展示产物；结构化框作为App绘制依据，两者坐标必须一致。统一处理EXIF方向和预处理后的坐标还原。
- 加入超时与错误状态。无检出、图片不可用和服务失败是不同结果，不能都返回空框并当作正常完成。
- 提供本地工位运行方式；若采用远程托管，连同依赖、启动脚本、鉴权和接口验证一起交付，保留本地备用方案。

### 4. 大模型与知识调用

- 接入一个团队可用的大模型API，供应商、版本、调用格式和预算上限明确登记。best.pt由YOLO加载，不交给大模型执行。
- 接收队员三提供的结构化知识条目与报告模板，先用简单检索组织证据，再生成解释、复检清单和报告草稿。
- 首轮必须支持围绕当前检测记录的追问；问题携带图片或批次上下文，不能串用其他记录。
- 将事实、引用、参考原因和待补信息分开输出。解析失败、超时或无依据时返回清楚状态，保留本地检测结果。
- 不将模型生成内容自动回写训练标签。知识更新和案例入库经过人工审核。

### 5. 记录、复核、统计与报告

- SQLite至少保存批次、图片、原始预测、分析结果、知识引用、人工复核、任务状态和版本。
- 人工修正以新记录保留原预测；提交包含所依据的版本，避免旧页面覆盖新复核。
- 批次统计区分图片数、模型框数与人工确认数。报告引用实际记录，不计算未经验证的产线合格率。
- 实现报告查询和约定的下载格式；队员三定义内容结构，队员二完成App端保存或分享。
- 实现WebSocket事件、任务状态恢复和去重配合；大模型失败不让已完成的检测重新变为失败。

交给队员三：真实实验结果、模型与接口版本、运行成本、已实现功能和失败限制；从队员三接收知识条目、报告模板与验收用例。大模型编排代码由你实现，知识事实由队员三组织审核。

## 六、完成标准

- [ ] 队员二能按说明连接，不需手工改你的电脑路径。
- [ ] 测试图片得到可追溯框和类别，原图坐标与App显示一致。
- [ ] 检测、分析、复核和报告可以完成一次真实闭环。
- [ ] 本地数据保存后重启可查询，人工修正保留原预测。
- [ ] 非法图片、空检出、API超时、断线分别返回可识别状态。
- [ ] 冻结测试集未参与调参，模型结果和失败样例如实记录。
- [ ] 云端密钥不在App、示例、公开材料和提交仓库中。

## 七、遇到工期压力时的取舍

保留单图检测、一个API、简单知识检索、一次复核与报告；批量、多模型对照的扩展规模、复杂托管、多种加速方案可后移。11月3日模型未稳定时先修数据和基线，不同时开发新算法。大模型不可用时返回固定模板与明确状态，后续补生成，不伪装实时结果。
