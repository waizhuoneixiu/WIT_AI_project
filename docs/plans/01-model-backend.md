# 钢见项目 · 模型与后端实施计划

版本日期：2026年10月30日。开发目录：`backend/`。模型、FastAPI/SQLite接口、DeepSeek/规则降级和魔搭部署已有代码与历史验证；下列云适配及复核补齐项仍待本轮实现与验证。

## 1. 已有基线与本轮职责

沿用 YOLO26n@640（Ultralytics 8.4.193）和已部署的魔搭Gradio/ONNX服务，见[模型卡](../../backend/docs/模型卡_n640.md)、[部署记录](../../backend/docs/魔搭部署记录.md)。本机只运行轻量业务API和SQLite，不安装YOLO、PyTorch、ONNX Runtime或本地大模型，不重新训练模型。

Android只连接业务API；后端负责魔搭令牌、云调用、图像方向和坐标、持久化、复核差异、分析与报告。以[共同契约](04-shared-contract.md)为实施协议，以[验收计划](05-integration-acceptance.md)决定完成。

## 3. 最小实现要求

- 在现有runtime入口适配云检测，不让API路径自行选择不同模型；现有低层接口与业务接口使用同一对外类别/坐标。模型信息不泄露本机路径或令牌。
- 图片格式/大小、解码、方向、云响应结构和框坐标均在信任边界验证；上传/调用/取结果有超时，云失败不可返回成功空框。同步云调用避免阻塞整个服务事件循环。
- `original_url` 指向统一方向后的持久原图；写文件、数据库及检测失败保持可辨错误，不能留下伪完成任务。
- 复核差异与版本严格按共同契约：base_version必填，省略/null corrections保留、[]重置，旧无op按update。新增UUID和原ID引用校验；修改或新增框score=null；原detections不覆盖。
- 详情返回reviewed_detections/review_version/original_url及最新analysis；复核后旧分析stale，按有效复核结果生成新分析。旧数据可读取，不要求清库迁移。
- 历史total应用同一筛选；批次per_class仍计原模型框，confirmed_count为图片数。本轮不扩展复核后类别统计。
- Markdown报告保存对应review_version，区分原预测、有效复核、备注与分析来源；旧report_id保持旧版本身份。云LLM失败明确rule_fallback，不下载本地模型兜底。

## 4. 验证与交付

先保存文档，再修改代码；先云检测，再复核与报告，最后同步样例和验收证据。对新分支/解析/校验增加小而有效的检查，复用现有脚本；至少验证无本地模型依赖启动、真实魔搭单图、超时错误、全部框差异、非法输入、409冲突、第二次编辑、原预测不变、重启恢复、筛选和报告版本。

交付API启动/配置说明、实际依赖与模型版本、可供Android使用的响应、测试结果及限制。既有训练资料保留来源，本轮不重复训练；GPU离线基准不能标成云调用总时延。

后续才评估批量、可靠异步队列、流式、其他云平台和新模型实验；完整框编辑、输入校验和数据保护不能因赶工省略。
