# 钢见项目 · KMP Android 实施计划

版本日期：2026年10月30日。开发目录：`frontend/`。文档先于代码保存；Android工程与页面按下列工作包实施。当前业务fixture已验证并导出，App完成状态仍须构建与设备证据，不能由后端合成流程推定。

## 1. 交付与技术边界

采用 Kotlin Multiplatform 与 Compose Multiplatform，首轮只交付 Android。共享数据模型、网络调用与业务状态；选图、拍照、文件保存/分享使用 Android 平台能力。当前构建选定 AGP 9.1.1、compileSdk 37.0（满足 Compose 要求）、targetSdk 36、minSdk 26；构建及设备兼容性仍待实测。前端只调用本机轻量 FastAPI 业务服务，由其调用魔搭 YOLO26n@640 与 DeepSeek 云 API；前端不携带云令牌，本机不安装模型运行库。

必须完成单图选图/拍照、批次号、检测与原图框、完整框编辑、人工复核、上下文问答、历史/批次及 Markdown 报告。不扩展批量、其他平台、完整流式、语音和持久离线上传队列。

接口、类别、字段及兼容行为统一见 [共同契约](04-shared-contract.md)，避免在页面中另造模型或统计口径。

## 2. UI 与页面

**每次编写 UI 代码前必须读取 [frontend/Aboard-design.md](../../frontend/Aboard-design.md)。** 采用 `#fafafa` 画布、白色面板、`#262626` 正文、柔和粉彩卡片、24dp 卡片圆角和胶囊操作。参考中部分强调色描述互相冲突，按其按钮组件使用蓝色主操作，满足文字对比度；手机以适配字号和留白为准，不照搬 64px 网页标题、营销文案或桌面三列。

主导航为“检测、记录、助手、我的”，结果详情从检测或记录进入。常用操作至少 48dp 触控目标，状态有文字，框操作另有可访问按钮/数值输入，不能只靠颜色和拖拽。

| 页面 | 必须行为 | 关键状态 |
|---|---|---|
| 检测 | 系统选图/拍照、图片预览、批次与可选工件编号、提交 | 无图片、取消采集、校验失败、提交中、失败重试 |
| 结果详情 | 原图与原预测/复核结果切换、缺陷列表、框选择与编辑、复核表单、分析/报告入口 | 未检出、待复核、已确认、已修正、无法判断、版本冲突 |
| 助手 | 明示当前图片或批次上下文、分析五类信息、文字问答和来源 | 无上下文、生成中、规则降级、失败、分析已过时 |
| 记录与批次 | 分页列表、批次/类别/复核状态筛选、详情恢复、原模型统计和报告 | 空列表、加载失败、分页末尾 |
| 我的与设置 | 业务 API 地址、必要的业务访问 Key、健康/版本/上传说明 | 可达、不可达、鉴权错误、云检测不可用 |

## 3. 按顺序实施

| ID | 工作包 | 完成条件 |
|---|---|---|
| F-01 | Android 工程与主题 | 固定实际构建版本，可构建/安装；落实设计参考和四入口 |
| F-02 | 契约与页面状态 | 与后端字段一致，成功/空/等待/错误夹具可验证；测试数据不混入正式记录 |
| F-03 | 采集与同步检测 | 选图/拍照、批次校验、防重复点击；一次真实云检测成功 |
| F-04 | 原图显示与框变换 | 原图尺寸、方向、等比缩放留白、缩放查看后框准确贴合 |
| F-05 | 完整复核编辑 | 新增、改类、移动、缩放、删除，生成相对原预测的完整差异 |
| F-06 | 保存与恢复 | 强制 base_version，409 刷新处理；离开/重开后原预测和复核结果一致 |
| F-07 | 分析与问答 | 当前上下文明确；source、引用和 stale 可见，失败不丢检测 |
| F-08 | 历史与批次 | 分页筛选总数正确，统计标签明确为原模型预测，重启仍可查看 |
| F-09 | 报告与连接 | Markdown 内容对应当前复核版本，可保存/分享；云故障可恢复 |
| F-10 | 构建与设备验收 | 关键单元检查、APK、真实流程截图/记录和已知限制 |

### 图片、坐标与完整框编辑

- 上传 jpg/jpeg/png/bmp，单张不超过 10MB。采集图像先统一方向，使用服务端 `original_url` 和返回宽高作为持久详情的绘制基准。
- 屏幕框由原图像素坐标经同一缩放/平移变换计算；编辑时反算回原图并限制在图内，禁止零面积或反向坐标。缩放查看不能改变保存的原图坐标。
- 新框用 UUID；原框沿用 detection_id。支持选框、修改类别、移动/缩放、删除和恢复原预测；草稿未提交前不伪装为已保存。
- 每次提交发送相对 `detections` 的完整 add/update/delete 差异，而非相对上次提交的增量。手工新增或修改框不展示模型分数；原预测保持可查。
- `base_version` 使用最新详情的 `review_version`；冲突后保留本地草稿供参考并要求重新检查，不自动覆盖远端结果。

### 请求、恢复与报告

- 检测、分析、问答使用同步 HTTP。按钮等待期间禁用，显示真实操作阶段；不连接仅回放最终结果的 WS 来伪造进度。
- 保存已返回的 inspection_id/task_id，重新进入通过详情或任务快照恢复。上传响应丢失且没有编号时提示先查记录，不自动重新创建；用户明确重试后才发新请求。
- 分析的 `source` 区分云 API 与规则模板；`stale=true` 提醒它基于旧复核版本，可重新生成。切换上下文即切换消息显示，避免串图；聊天回答的review_version/stale说明实际依据版本，stale=true时提示重新询问，批次回答版本为null。
- 报告读取 `content_md` 和 `review_version`，保存 `.md` 或系统分享；报告应含原预测、当前人工结果/备注、分析来源与版本。不自行用旧缓存拼成新报告。
- 未检出显示“未检出六类目标缺陷”；云调用失败显示失败，不能当空结果。业务 API 或外网不可达时不承诺离线检测。

## 4. 验收与交付

按 [联调用例](05-integration-acceptance.md) 完成真实单图、全部编辑操作、版本冲突、方向/留白、多框、空结果、云失败、规则降级和重启恢复。报告验证保存文件，不只检查按钮。

交付源码、实际构建/依赖版本、APK、连接与安装说明、真实流程证据及已知限制。界面截图必须说明是真实云调用还是测试夹具；若缺少设备/环境，明确记录未验收项，不能预填通过。
